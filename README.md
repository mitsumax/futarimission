# ふたりミッション（サーバー版）

知らない二人がチャットしながら協力ゲームに挑戦する Web アプリです。登録不要で、スマホでも PC でもブラウザだけで遊べます。

- **マッチング**：性別に関係なく完全ランダムです。性別（男性・女性・ひみつ）は相手に表示するだけで、絞り込みには使いません。
- **ゲーム**：💞 以心伝心、🔐 記号ロック、🌫️ 霧の迷路の 3 種類です。
- **判定はすべてサーバー側**：暗号や迷路の地図など、相手に見えてはいけない情報は相手の端末に送られません。
- **依存パッケージなし**：Node.js 18 以上があれば `npm install` なしで起動できます。

---

## 1. 手元で動かす

```bash
node server.js
# → http://localhost:3000 を2つのブラウザ（またはシークレットウィンドウ）で開く
```

スマホから試すときは、PC と同じ Wi-Fi につないで `http://<PCのIPアドレス>:3000` を開きます。

テスト（Node.js 22 以上）:

```bash
npm test     # ゲームのルール・フィルター（12件）＋サーバーとの通信（9件）
```

## 2. インターネットに公開する

WebSocket が使える Node.js のホスティングなら、どこでも動きます。HTTPS（`wss://`）は各サービスが自動で付けてくれます。

### Render（かんたん・無料枠あり）
1. このフォルダを GitHub にアップロードする
2. Render で **New → Web Service** を選び、リポジトリを指定する
3. Build Command は空欄、Start Command は `node server.js`
4. 環境変数（Environment）を設定する：`TRUST_PROXY=1`、`HASH_SALT=（長いランダム文字列）`、`ADMIN_TOKEN=（長いランダム文字列）`
5. 通報ログを残すなら **Disk** を追加し、`DATA_DIR` をそのマウント先にする

> 無料プランは、しばらくアクセスがないとスリープし、通報ログ用のディスクもありません。本番では有料プランか、次の方法をおすすめします。

### Railway / Fly.io / VPS（Docker）
```bash
docker build -t futari .
docker run -p 3000:3000 -e TRUST_PROXY=1 -e HASH_SALT=... -e ADMIN_TOKEN=... -v $(pwd)/data:/app/data futari
```
VPS で nginx を前に置く場合は、`/ws` に WebSocket のアップグレード設定（`proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade";`）が必要です。

> **注意：サーバーは 1 台（1 プロセス）で動かしてください。** マッチングの待ち行列とゲームの状態をメモリで持っているので、複数台に分けると別のサーバーにいる人どうしがマッチングできません。1 台で数千人の同時接続までは十分さばけます。それ以上の規模になったら、Redis などで状態を共有する作りに変えます。

## 3. 環境変数

| 変数 | 内容 | 既定値 |
|---|---|---|
| `PORT` | 待ち受けるポート | 3000 |
| `TRUST_PROXY` | `1` にすると `X-Forwarded-For` から利用者の IP を取る（Render・Fly・nginx の後ろに置くときは必須） | なし |
| `HASH_SALT` | 通報ログ・BAN 用に IP をハッシュ化するときのソルト。**必ず設定**（未設定だと再起動のたびに変わり、BAN が引き継がれない） | 起動ごとにランダム |
| `ADMIN_TOKEN` | 設定すると管理用 API が有効になる | なし |
| `ALLOWED_ORIGINS` | `/ws` への接続を許可するオリジン（カンマ区切り）。未設定なら同じホストからの接続だけ許可 | なし |
| `DATA_DIR` | 通報ログ・BAN リストの保存先 | `./data` |
| `MAX_CONN_PER_IP` | 1 つの IP からの同時接続の上限 | 30 |

## 4. 運営・安全対策

| 仕組み | 内容 |
|---|---|
| 連絡先ブロック | 電話番号、メールアドレス、URL、@ID、LINE・インスタ・Discord などを含む発言は送れない（`filter.js` で調整） |
| NG ワード | 悪口などをブロック。**性的な語や差別語は、運営方針に合わせて `NG_WORDS` に追加してください** |
| 連投制限 | 6 秒間に 5 通まで |
| ブロック | ブロックした相手とは二度とマッチングしない（同じブラウザのタブを開いている間） |
| 通報 | 理由と、その時点の直近の会話（最大 40 件）を `data/reports.jsonl` に記録。IP はハッシュ化して保存し、生の IP は残さない |
| 自動 BAN | 24 時間以内に別々の 3 人から通報されると、その IP を 24 時間利用停止 |
| 再マッチ防止 | 直前の相手とは 3 分間マッチングしない |
| 再接続 | 電波が切れても 20 秒以内に戻れば同じゲームに復帰 |
| チャットの保存 | **しない**。通報があったときだけ、確認のために記録 |

管理用 API（`ADMIN_TOKEN` を設定したときだけ有効）:

```bash
curl -H "x-admin-token: $ADMIN_TOKEN" https://<ドメイン>/admin/stats     # 接続数・待機数・ペア数
curl -H "x-admin-token: $ADMIN_TOKEN" https://<ドメイン>/admin/reports   # 通報ログ（JSON Lines）
```

**IP による BAN の限界**：スマホの回線は、多くの人が 1 つの IP を共有していることがあります（CGNAT）。そのため、IP での BAN は無関係な人を巻き込んだり、機内モードの切り替えなどで回避されたりします。荒らしが増えてきたら、次のような対策を検討してください。
- Cloudflare Turnstile（無料・見えない CAPTCHA）を、マッチング開始時に入れる
- 通報ログを人が確認する運用にする

## 6. ファイル構成

フォルダを使わず、全ファイルを1か所に並べています。GitHubへは、全ファイルを選んでドラッグするだけでアップロードできます。

```
server.js          HTTP・WebSocket・マッチング・ペア管理・通報/BAN
ws.js              依存なしの WebSocket 実装（RFC 6455）
games.js           ゲームのルールと「役割ごとに見せる情報」の切り分け
filter.js          連絡先・NG ワード・ニックネームのフィルター
index.html         画面（スマホ/PC 共通・1 ファイル）
favicon.svg        アイコン
test-unit.js       ユニットテスト
test-protocol.js   通信テスト
```

外部に公開されるのは index.html と favicon.svg だけです。server.js などのプログラムは、ブラウザから見えません。

### ゲームを増やすには
1. `games.js` の `startGame` に初期状態、`apply` に操作の処理、`view` に役割ごとの見せ方を書く
2. `GAME_IDS` に ID を追加する
3. `index.html` の `GAMES` に名前と説明を追加し、`renderStage` に描画処理を書く
