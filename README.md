# ふたりミッション（サーバー版）

知らない二人がチャットしながら協力ゲームに挑戦する Web アプリです。登録不要で、スマホでも PC でもブラウザだけで遊べます。

- **マッチング**：完全ランダムです。**性別は聞かず、表示もしません**（ニックネームだけで遊べます）。出会い目的のアプリと誤解されないための設計です。
- **AIと遊ぶ**：トップ画面の「🤖 AIと遊ぶ」、または相手を探している画面の「待っている間、AIと遊ぶ」で、プログラムで動くAI「ロボ」とすぐ遊べる（`bot.js`）。外部のAIサービスは使わず、費用ゼロ・外部送信なし。7種類すべてのゲームで相手役になり、チャットで伝えた内容（「三角の中に点」「右に2マス」「🍎は左下」など）を読み取って動く。隠された情報をのぞくことはせず、自分の画面とチャットだけで判断する。AIであることは常に画面に表示し、通報の対象外。
- **友だちを招待**：「部屋を作って招待」で6文字の招待コードとリンクができる。リンクを開いた人は、ニックネームを入れるだけでその部屋に入れる（コードを手入力して入ることもできる）。部屋は1回使うと閉じ、使われなければ30分で期限切れ。コードの当てずっぽう入力は1分に12回までに制限。ブロックした相手は部屋にも入れない。
- **ゲーム（7 種類）**
  - 💞 **以心伝心**：同じ質問に答えて、6問中4問そろえばクリア。
  - 🔐 **記号ロック**：片方にだけ見える暗号を言葉で伝えて入力する。
  - 🌫️ **霧の迷路**：地図が見えるナビ役が、まわりしか見えない探検役を道案内する。
  - 🎨 **お絵かき伝言**：お題を絵で描いて当てる。1問80秒、3問中2問正解でクリア。描く人は答えをチャットに書けない。
  - 🧩 **ふたりパズル**：自分のピースの正解位置は相手にしか見えない。教え合って9マスを完成させる（答え合わせは3回まで）。
  - 🃏 **合わせて○○**：相手のカードは見えない。数字を言わずにヒントだけで、2人のカードの合計を目標の数にする（チャットで数字は送れない）。
  - 💣 **NGワードトーク**：お題（夏休み、カレーなど20種類）について3分間おしゃべりする。お題に関係するNGワードが3つ隠れていて、チャットで言ってしまった人の負け。黙っているだけで勝てないように、1人5回以上（5文字以上の発言）話すノルマがある。2人とも生き残ればクリア。終了後に隠れていたNGワードを公開。お題とNGワードは `games.js` の `NG_TOPICS` で追加・変更できる（短いひらがなは日常の言葉に紛れやすいので避ける。`npm test` で誤判定チェックが走る）。
- **遊び終わったあと**：「たのしかった！」「ナイスチーム！」などのスタンプを相手に送れる。退出するときにも送れる。
- **既読**：相手がアプリの画面を見ている状態でメッセージを受け取ると、自分のメッセージの下に「既読」と出る（相手が別のアプリを開いている間は付かず、戻ってきた時点で付く）。サーバーは「何番目まで読んだか」の数字だけを中継し、保存しない。
- **効果音**：マッチング、正解、クリアなどで音が鳴る（右上の🔊でオン/オフ）。音声ファイルは使わず、ブラウザで合成している。
- **判定はすべてサーバー側**：暗号や迷路の地図など、相手に見えてはいけない情報は相手の端末に送られません。
- **依存パッケージなし**：Node.js 18 以上があれば `npm install` なしで起動できます。

---

## 1. 手元で動かす

```bash
node server.js
# → http://localhost:3000 を2つのブラウザ（またはシークレットウィンドウ）で開く
```

スマホから試すときは、PC と同じ Wi-Fi につないで `http://<PCのIPアドレス>:3000` を開きます。

テスト（Node.js 22 以上）:

```bash
npm test     # ゲームのルール・フィルター（12件）＋サーバーとの通信（9件）
```

## 2. インターネットに公開する

WebSocket が使える Node.js のホスティングなら、どこでも動きます。HTTPS（`wss://`）は各サービスが自動で付けてくれます。

### Render（かんたん・無料枠あり）
1. このフォルダを GitHub にアップロードする
2. Render で **New → Web Service** を選び、リポジトリを指定する
3. Build Command は空欄、Start Command は `node server.js`
4. 環境変数（Environment）を設定する：`TRUST_PROXY=1`、`HASH_SALT=（長いランダム文字列）`、`ADMIN_TOKEN=（長いランダム文字列）`
5. 通報ログを残すなら **Disk** を追加し、`DATA_DIR` をそのマウント先にする

> 無料プランは、しばらくアクセスがないとスリープし、通報ログ用のディスクもありません。本番では有料プランか、次の方法をおすすめします。

### Railway / Fly.io / VPS（Docker）
```bash
docker build -t futari .
docker run -p 3000:3000 -e TRUST_PROXY=1 -e HASH_SALT=... -e ADMIN_TOKEN=... -v $(pwd)/data:/app/data futari
```
VPS で nginx を前に置く場合は、`/ws` に WebSocket のアップグレード設定（`proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade";`）が必要です。

> **注意：サーバーは 1 台（1 プロセス）で動かしてください。** マッチングの待ち行列とゲームの状態をメモリで持っているので、複数台に分けると別のサーバーにいる人どうしがマッチングできません。1 台で数千人の同時接続までは十分さばけます。それ以上の規模になったら、Redis などで状態を共有する作りに変えます。

## 3. 環境変数

| 変数 | 内容 | 既定値 |
|---|---|---|
| `PORT` | 待ち受けるポート | 3000 |
| `TRUST_PROXY` | `1` にすると `X-Forwarded-For` から利用者の IP を取る（Render・Fly・nginx の後ろに置くときは必須） | なし |
| `HASH_SALT` | 通報ログ・BAN 用に IP をハッシュ化するときのソルト。**必ず設定**（未設定だと再起動のたびに変わり、BAN が引き継がれない） | 起動ごとにランダム |
| `ADMIN_TOKEN` | 設定すると管理用 API が有効になる | なし |
| `ALLOWED_ORIGINS` | `/ws` への接続を許可するオリジン（カンマ区切り）。未設定なら同じホストからの接続だけ許可 | なし |
| `DATA_DIR` | 通報ログ・BAN リストの保存先 | `./data` |
| `MAX_CONN_PER_IP` | 1 つの IP からの同時接続の上限 | 30 |
| `PUBLIC_URL` | リンクの見た目（OGP）とシェアボタンに使う公開アドレス | https://futarimission.com |
| `MIN_AGE` | 利用できる年齢の下限。トップ画面・利用規約・プライバシーポリシーに表示される | 18 |
| `CONTACT_EMAIL` | 利用規約・プライバシーポリシーに載せる問い合わせ先（Renderで設定するとそちらが優先） | postmaster@futarimission.sakura.ne.jp |
| `OPERATOR_NAME` | 規約に載せる運営者名 | ふたりミッション運営者 |
| `STORE_URL` / `STORE_TOKEN` | 記録の保存先（7章） | なし（このサーバーのファイルに保存） |
| `STORE_PROVIDER` | プライバシーポリシーに書く保存先の説明 | GMOデジロック「コアサーバー」 |
| `POLICY_UPDATED` | 規約の「最終更新日」 | 2026年11月14日 |

## 4. 運営・安全対策

| 仕組み | 内容 |
|---|---|
| 連絡先ブロック | 電話番号、メールアドレス、URL、@ID、LINE・インスタ・Discord などを含む発言は送れない（`filter.js` で調整） |
| NG ワード | 悪口などをブロック。**性的な語や差別語は、運営方針に合わせて `NG_WORDS` に追加してください** |
| 連投制限 | 6 秒間に 5 通まで |
| ブロック | ブロックした相手とは二度とマッチングしない（同じブラウザのタブを開いている間） |
| 通報 | 理由と、その時点の直近の会話（最大 40 件）を `data/reports.jsonl` に記録。IP はハッシュ化して保存し、生の IP は残さない。**180日で自動削除**（プライバシーポリシーに記載） |
| 自動 BAN | 24 時間以内に別々の 3 人から通報されると、その IP を 24 時間利用停止 |
| 再マッチ | ブロックしていなければ、同じ相手・同じ IP（同じ Wi-Fi）でもすぐ再マッチできる。ほかに待っている人がいれば、3 分間は新しい相手を優先する |
| 再接続 | 電波が切れても 20 秒以内に戻れば同じゲームに復帰。相手の接続が切れたこと・戻ったこと・戻らずに終了したことは、チャット欄にシステムから表示し、ヘッダーに残り秒数を出す。電波が突然切れた場合も約20秒以内に検知（10秒ごとの生存確認） |
| チャットの保存 | **しない**。通報があったときだけ、確認のために記録 |

### 管理画面

`https://<ドメイン>/admin` を開き、Render の環境変数に設定した `ADMIN_TOKEN` を入力します（`ADMIN_TOKEN` が未設定だとログインできません）。

- いま接続中の人数、相手を探している人数、遊んでいるペアの数、24時間の通報数
- 通報の一覧（新しい順）：理由と通報時の会話。ボタンで「24時間停止」「30日停止」「停止を解除」「対応済みにする」ができる
- 利用停止中の一覧と解除

一覧は15秒ごとに自動で更新されます。

**IP による BAN の限界**：スマホの回線は、多くの人が 1 つの IP を共有していることがあります（CGNAT）。そのため、IP での BAN は無関係な人を巻き込んだり、機内モードの切り替えなどで回避されたりします。荒らしが増えてきたら、次のような対策を検討してください。
- Cloudflare Turnstile（無料・見えない CAPTCHA）を、マッチング開始時に入れる
- 通報ログを人が確認する運用にする

## 6. ファイル構成

フォルダを使わず、全ファイルを1か所に並べています。GitHubへは、全ファイルを選んでドラッグするだけでアップロードできます。

```
server.js          HTTP・WebSocket・マッチング・ペア管理・通報/BAN
ws.js              依存なしの WebSocket 実装（RFC 6455）
games.js           ゲームのルールと「役割ごとに見せる情報」の切り分け
filter.js          連絡先・NG ワード・ニックネームのフィルター
index.html         画面（スマホ/PC 共通・1 ファイル）
admin.html         管理画面（/admin）
favicon.svg        アイコン
test-unit.js       ユニットテスト
test-protocol.js   通信テスト
```

外部に公開されるのは index.html・admin.html・favicon.svg だけです（管理画面のデータは ADMIN_TOKEN がないと読めません）。server.js などのプログラムは、ブラウザから見えません。

### ゲームを増やすには
1. `games.js` の `startGame` に初期状態、`apply` に操作の処理、`view` に役割ごとの見せ方を書く（制限時間があるなら `tick`、ゲーム中のチャット制限があるなら `chatGuard` も）
2. `GAME_IDS` に ID を追加する
3. `index.html` の `GAMES` に名前と説明を追加し、`renderStage` に描画処理を書く

## 7. 記録をレンタルサーバー（コアサーバー）に保存する

Render の無料プランは、再起動や更新のたびにファイルが消えます。通報・利用停止・対応済みの記録だけを、PHP が動くレンタルサーバー（コアサーバーなど）に保存できます。

1. `php-store/store.php` の `__STORE_TOKEN__` を、32文字以上のランダムな合言葉に書き換える。
2. レンタルサーバーの公開フォルダに `futari-store` などのフォルダを作り、`store.php` をアップロードする（記録はその中の `data/` に自動で作られる。ブラウザで直接開いても中身は表示されない）。
3. Render の環境変数に、次の2つを設定する。
   - `STORE_URL` … `https://（レンタルサーバーのドメイン）/futari-store/store.php`
   - `STORE_TOKEN` … 手順1と同じ合言葉
4. 管理画面（/admin）の「記録の保存先」が「レンタルサーバー（接続OK）」になれば完了。

- 通信内容は Base64 で送るので、チャットの文章がレンタルサーバーの WAF に誤ってブロックされにくくなっている。
- レンタルサーバーに一時的につながらなくても、記録はアプリ側にためておき、30秒ごとに再送する。つながるまでは利用停止の一覧を上書きしない。
- 通報記録の180日での自動削除は、レンタルサーバー側でも行う。
- `npm test` には、PHP があれば `store.php` を実際に動かすテストが含まれる。
